# SVARĀ V3 — Master Product Upgrade and Implementation Specification

## 1. Product vision
Transform SVARĀ into a professional, premium-quality Android music player that delivers an immersive, highly customizable, visually rich, and reliable offline listening experience. It must go beyond the conventional music-player layout: cinematic transitions, sophisticated artwork presentation, rich audio controls, personalized layouts, Android home-screen widgets, and dependable background playback. It plays music stored locally through authorized file or folder access. No online catalogue, cloud streaming, or mandatory accounts. Core principle: one powerful music engine, five distinctive visual identities, extensive customization, and a consistently smooth user experience.

## 2. Preserve the existing project
Inspect current source, architecture, dependencies, navigation, playback engine, theme system and persistence. Identify which V2.1 features are implemented, partial or missing. Reuse working functionality. Preserve the five themes (Anāhata Signature, Shruti Muse, Tāla Pulse, Rāga Rang, Spanda Flux), the 64-colour palette, custom hue slider, theme-specific accents, cached album-artwork colour extraction, ambient gradients, accessible contrast and EffectsPolicy. Retain fixes for sans-serif typography, mini-player marquee clipping, Rāga header spacing and high-contrast preset identity. Preserve the shared queue, library, settings and playback state when switching themes. Avoid placeholder screens, mock data or non-functional controls. No wholesale rewrite; implement incrementally with regression tests after each major feature group.

## 3. Upgrade the visual design system
Direction: cinematic album artwork; layered backgrounds from artwork colours; controlled translucent surfaces; elegant sans-serif typography with clear hierarchy; subtle borders, shadows, gradients and depth; generous spacing; fluid transitions and micro-interactions; layouts that adapt to theme and screen size. Avoid excessive glassmorphism, oversized text, unnecessary decoration and indiscriminate blur.
Artwork presentation system: square album cards, portrait cards, wide playlist covers, layered compositions, large immersive Now Playing artwork, blurred ambient backgrounds, optional subtle parallax and lift, shared-element transitions between library cards and Now Playing. Preserve aspect ratio; generate and cache appropriately sized thumbnails. Missing artwork uses the deterministic album/file colour, a tasteful music symbol and available metadata.
Dynamic ambient environment: extend the existing colour engine; reuse the cached palette for ambient gradients on Home, Now Playing, mini-player and playlist cards; about 600 ms transitions on track or artwork change; static between changes; never compromise text readability, battery or scrolling.

## 4. Redesigned listening experience
A. Immersive Now Playing: large artwork; album, track and artist; favourite with satisfying animation; play/pause, previous, next, seek; elapsed and remaining time; queue; lyrics when available; audio information and equalizer shortcuts; sleep timer; shuffle and repeat; optional aura and glow; expandable controls; gestures. Three styles: Classic, Cinema, Compact, sharing one engine and state.
B. Enhanced queue: reorder, remove, clear with confirmation or undo, play next, add to queue, save as playlist, clear upcoming display, preserve current track and position while editing, smooth drag and drop, persisted, stable under rapid edits.
C. Rich library: Songs, Albums, Artists, Folders, Playlists, Recently played, Recently added, Most played, Favourites, Listening history. Sorting by title, artist, album, date added, duration and other supported metadata. Fast metadata search, filtering, multi-select, bulk playlist additions, bulk favourite changes, folder exclusions, incremental rescanning, duplicate detection, missing-artwork and missing-metadata indicators. No repeated full scans on screen open. Preserve access permissions; recover when files are moved, deleted or inaccessible.
D. Playlist Studio: create, rename, reorder, duplicate, delete; choose artwork or automatic compositions; descriptions and ordering; add from multiple screens; export and import local formats; save queue as playlist. Rule-based smart playlists from local metadata (recently added, most played, favourites, artists, albums, folders, manual criteria). No mood tagging or inference.

## 5. Synchronized local lyrics
Embedded lyrics, imported LRC, plain text, manual import and editing; time-synchronized highlighting; automatic scrolling; full-screen presentation; adjustable text size and line spacing; optional lyrics backgrounds from the artwork palette. When unavailable, offer an import action rather than pretending to retrieve lyrics online. Parsing and file operations off the main thread. No internet.

## 6. Rich audio-control suite
Equalizer: supported bands, sliders, presets (Flat, Bass Boost, Treble, Vocal, Classical where supported), user presets, reset, clear unsupported indication. Playback controls where supported: speed, optional pitch preservation, gapless, configurable crossfade, ReplayGain or equivalent, configurable seek increments, sleep timer with optional fade-out. Do not promise bit-perfect playback, hardware-specific effects, gapless transitions or equalizer compatibility unless verified on the target device and implementation. Audio processing must not cause dropouts or depend on UI animation timing; core playback continues if visual effects or enhancements fail.

## 7. SVARĀ Spanda immersive visualizer
Gallery: Waveform, Spectrum bars, Circular spectrum, Minimal ambient pulse, Album aura, Full-screen immersive. Adjustable: intensity, number of bars, glow, background opacity, colour source, artwork visibility, animation sensitivity, full-screen mode. Use supported audio-data sources and lightweight signal processing; smooth band values before rendering. Pause or reduce rendering when hidden, screen off or no active visualizer session. No continuous background visualization without user benefit. Playback independent of visualizer rendering.

## 8. Native Android home-screen widgets
Real Android widgets integrated with the app architecture.
Small: artwork thumbnail, track title, artist, play/pause, previous and next where space allows.
Medium: artwork, track and artist, controls, progress indicator where supported, theme-aware background.
Large: larger artwork, track information, controls, seek/progress presentation where supported, optional queue or favourite shortcut.
Customization: size, artwork visibility, background style, transparent/solid/translucent where supported, accent source, text and control visibility, compact or expanded. Use the current preset or a user-selected widget style; honour custom colour and artwork palette when feasible.
Behaviour: reflect the real playback state; controls operate on the real service; update after track changes, playback changes and appearance changes; handle taps when the app process is not visible; respect widget update and background-execution limits; no high-frequency updates; use Android-supported mechanisms. Document system-imposed limitations (progress updates, transparency, launcher differences).

## 9. Android integration
Persistent background playback; MediaSession; notification controls; lock-screen controls and artwork where supported; Bluetooth headset and media buttons; audio focus; pause, resume and interruption behaviour; headphone disconnection; audio routing changes; correct service lifecycle; recovery from process recreation where supported; notification permission on applicable versions; battery-aware background behaviour. Music must not stop because the user navigates away or locks the screen. Follow current foreground-service, media-playback, storage-access and permission requirements for the target SDK.

## 10. Personalization without fragmentation
Keep the Appearance page as the main hub. Retain: theme selection, 64 swatches, hue slider, preset/album-artwork/custom-accent/monochrome sources, background tone, light/dark/system, ambient intensity, blur controls, motion intensity, performance mode, section resets, reset everything, save as look, links to advanced studios. Extend saved looks: duplicate, rename, preview, restore. Add optional customization for: Home section order, visible navigation destinations, Now Playing presentation, mini-player behaviour, artwork size and shape, gesture mappings, animation intensity, visualizer presentation, widget appearance. Persist locally using configuration overrides rather than duplicated implementations per theme.

## 11. Quality-of-life features
Sleep timer; undo for accidental playlist or queue changes; recently deleted playlist recovery where safely supported; listening history and local play counts; Music Library Doctor (duplicates, missing artwork, incomplete metadata); user-confirmed metadata corrections that never modify original audio unexpectedly; playlist and settings backup/export to user-selected local destinations; configurable default startup screen; search shortcuts; one-handed options; optional haptics; accessible labels; reduced motion; empty, loading, error and permission-denied states for every major screen. Statistics stay local; no telemetry, tracking, sync or accounts.

## 12. Performance engineering
Lazy lists with stable identities; isolate frequently changing playback state from static library content; cache artwork thumbnails and palettes; metadata scanning, sorting, parsing and image processing off the main thread; avoid repeated widget rebuilds for progress; prefer transforms and opacity; limit large live blur surfaces; never blur scrolling lists; reuse cached low-resolution backgrounds; pause off-screen animations; bound caches; dispose resources correctly; adapt to performance mode, battery saver and reduced motion. Modes: Efficiency, Balanced, Immersive. Targets set by profiling on physical devices; aim for smooth 60 FPS, higher refresh rates where feasible. Test long sessions for memory growth, battery drain, audio interruptions and thermal throttling.

## 13. Accessibility and usability
WCAG AA (4.5:1 normal text, 3:1 large text). Accessible labels, screen-reader support, focus states, mobile-appropriate touch targets, reduced motion, selected states beyond colour, readable text scaling, confirmation for destructive actions, helpful permission explanations, clear error recovery. Ambient colours never reduce text readability.

## 14. Production architecture and data safety
Separate UI, playback engine, media-session integration, library discovery, metadata and persistence, artwork processing and caching, audio analysis, widget integration, theme and appearance configuration. Use the existing native Android stack and extend the current architecture. Use the existing database with additive migrations; never delete user playlists, settings, history or other data during upgrades. Handle permission revocation, unavailable files, corrupt metadata, unsupported formats, migration errors and interrupted operations gracefully.

## 15. Testing requirements
Automated tests for: playback state and queue; theme and appearance persistence; all 64 accents; palette caching and fallback colours; high contrast; playlist create/edit/import/export; lyrics parsing and sync; sleep timer; audio interruption; widget commands and state updates; permission denial and revocation; database migrations; recovery after activity or process recreation. Integration tests: main listening journey, library scanning, theme switching during playback, background playback, widget interaction. Physical-device testing for audio routing, background playback, widgets, battery and visual performance. No feature is complete solely because its screen renders.

## 16. Deployment readiness
Release build succeeds; app ID, package, version code and name correct; icon, adaptive icon, splash and branding polished; runtime permissions justified and requested at the right time; privacy policy accurate; no debug menus, mock data, test tokens or dev endpoints in release; secure signing configuration; compatible dependencies and SDKs; correct behaviour on supported Android versions; appropriate crash handling; backup, migration and upgrade tested; release checklist and known-limitations document produced. Do not claim store approval or production readiness until the real build and checks are complete.

## 17. Implementation strategy
Phase 1 Foundation and visual polish. Phase 2 Core listening improvements. Phase 3 Immersive experience. Phase 4 Android integration. Phase 5 Quality and release. After each phase report what was implemented, files changed, tests run, what passed or failed, and what remains incomplete.

## 18. Definition of done
Existing V2.1 functionality intact; new screens in real navigation and state; playback, queue, library and playlists work with real local files; lyrics, visualizers and audio controls function within supported capabilities; widgets are genuinely installed and interactive; theme and appearance settings persist across restarts; background playback reliable; accessibility and reduced motion work; performance measured on physical devices; automated tests pass and failures documented; a signed release build can be generated; no advertised control is merely decorative or backed by fake data.

Final standard: SVARĀ should feel like a carefully crafted premium music application: visually distinctive, fluid, deeply customizable, dependable for everyday listening, respectful of user privacy, and practical to maintain and release.
