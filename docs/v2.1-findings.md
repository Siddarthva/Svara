## Defects

### a. High contrast forces a yellow accent on every preset

**Root cause.** High contrast replaces colours instead of strengthening them, in two places:
- `ui/theme/Theme.kt:34–60`: `HighContrastDark` / `HighContrastLight` are fixed Material schemes with `primary = #FFE066` (dark) and `#1A0080` (light). `SvaraTheme` (`Theme.kt:80–82`) uses them instead of the preset's scheme whenever High contrast is on, so every shared screen gets the same yellow accent.
- `ui/theme/PresetTheme.kt:210–222`: `highContrastPalette()` builds a fixed black/white palette with `accent = #FFE066` (dark) and `#1A0080` (light), replacing the preset's palette in every preset composable.

**Fix.** High contrast keeps the preset's (or custom) accent and raises contrast instead: text targets 7:1, non-text 4.5:1, accents are adjusted for lightness in a perceptual space (hue kept), secondary text is lifted toward primary, and outlines and dividers get thicker. One contrast engine does this for every preset.

### b. Text renders in a serif face

**Investigation.** No code path selects a serif family:
- Every layout preset builds its text styles with `FontFamily.SansSerif` (`ui/theme/PresetTheme.kt:225`, `toTextStyle`), and their Material typography comes from the same function.
- Anāhata's typography (`ui/theme/Theme.kt:164–169`, `family()`) maps `FontKind.SANS` to `FontFamily.SansSerif`. The `FontKind.SERIF` branch exists but no spec uses it since v2 (SHRUTI used it before).
- There is no font resource in `res/font`.

On the emulator (stock Roboto) all text is sans-serif, as expected.

**Root cause.** `FontFamily.SansSerif` and `FontFamily.Default` are not "Roboto"; they are the platform's `sans-serif` alias, which follows the phone's system font. Several manufacturers let users replace that font (font style settings and themes), and the replacement applies to apps that use the default family. On a phone set to a serif style, every SVARĀ screen renders in that serif face. The app relied on a default it doesn't control.

**Fix.** Bundle Roboto (Apache License 2.0; the same face Android ships), instanced to four static weights (400, 500, 600, 700) and subset to Latin plus the macron vowels the preset names use. Set it as the one family for every preset, both Material typographies and all token text styles. Remove the unused serif and condensed branches.

### c. Mini-player title clips at the left edge while the marquee scrolls

**Root cause.** `MarqueeText` (`ui/presets/common/PresetBasics.kt`, used by every layout preset's mini-player) applies `Modifier.basicMarquee()` to a `Text` in a `weight(1f)` column that starts right after the artwork spacer. `basicMarquee` clips its content to its own bounds with no fade, so as the text scrolls, glyphs are cut off hard at the left edge of that column, which reads as a rendering fault next to the artwork.

**Fix.** Fade both edges with a mask: draw the text offscreen and multiply a horizontal gradient at each end (draw phase only). The fade shows only while the text is overflowing and moving; at rest the text starts exactly at the left edge with no fade.

### d. RĀGA header: the language pill crowds the wordmark

**Root cause.** `ui/presets/raga/RagaScreens.kt:90–100` puts the wordmark, the language pill (in a `weight(1f)` box) and two 48 dp icon buttons in one row. At 130 % text scale, "SVARĀ" at h1 plus "Add language tags" at bodyEmphasis plus 96 dp of icons exceed a phone's width. The pill box gets only what's left, and the pill's single-line label (no ellipsis) overflows its box toward the wordmark.

**Fix.** Two rows: the wordmark with the search and settings icons on top, and the language pill on its own row below, single-line with an ellipsis. Both fit at 130 %.
